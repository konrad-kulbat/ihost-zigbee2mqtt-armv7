# Zigbee2MQTT for SONOFF iHost (ARMv7)

This is a deliberately small Home Assistant add-on repository for SONOFF iHost
running 32-bit ARMv7. It uses Zigbee2MQTT **2.14.1** and keeps the iHost add-on
contract: the default data directory is `/config/zigbee2mqtt`, the UI exposes
MQTT and serial settings, ingress is enabled, and UART/udev access is requested.

It is not a fork of Zigbee2MQTT. The image downloads the signed upstream release
tarball during its build and compiles its native serial binding for `linux/arm/v7`.

## One required repository customization

The GHCR image is published under the GitHub owner `konrad-kulbat`. Create or
use that GitHub repository, push this directory, and let the `main` workflow
finish. It publishes:

`ghcr.io/<owner>/ihost-zigbee2mqtt-armv7-armv7:2.14.1-ihost.1`

Make the resulting GHCR package public. Then add the GitHub repository URL in
Home Assistant: **Settings → Add-ons → Add-on store → ⋮ → Repositories**.

## Safe migration from the iHost add-on

1. Record the old add-on's options, especially `serial.port`, `serial.adapter`,
   MQTT options and `data_path`. The iHost default is `/config/zigbee2mqtt`.
2. Make a full backup of that directory while Zigbee2MQTT is stopped. At a
   minimum retain `configuration.yaml`, `database.db`, `coordinator_backup.json`
   (if present), `devices.yaml`, `groups.yaml`, `state.json`, custom converters,
   extensions and OTA files. Keep the backup outside the iHost.
3. Install this add-on but **do not start it**. Set `data_path` to the existing
   `/config/zigbee2mqtt`; enter the same serial and MQTT settings. Do not create
   a second data directory for a migration.
4. Stop the old `zigbee2mqtt` add-on. Only after it has stopped, start this one.
   Two processes must never open the same coordinator or data directory.
5. Read the first startup log. Zigbee2MQTT 2.x performs setting migration and
   backs up its prior `configuration.yaml`; preserve that backup. Resolve any
   schema warning before enabling join or OTA.
6. Confirm the frontend loads, MQTT bridge state is online, and devices report
   without re-pairing. The network key and device database remain in the same
   data directory; neither is regenerated by this add-on.

Do not use a new network key, delete `database.db`, or reset/reflash the
coordinator as part of this migration.

### Rollback

Stop this add-on. Restore the complete pre-migration directory backup (including
the original `configuration.yaml`, because 2.x may have migrated it), then start
the old iHost add-on. Do not run both add-ons during rollback.

## Updating Zigbee2MQTT

1. Read every upstream release note from the installed version through the target.
2. Change `ZIGBEE2MQTT_VERSION` in `zigbee2mqtt/build.env`, the add-on version
   in `zigbee2mqtt/config.json` to `<z2m>-ihost.N`, and `BUILD_VERSION` plus tags
   in `.github/workflows/ci.yml`.
3. Run a pull request build; it cross-builds `linux/arm/v7`. Publish only after
   the manifest inspection reports `linux/arm/v7`.
4. Back up the live data directory before installing the new add-on version.

## Local build

On a Linux Docker host with Buildx and QEMU:

```sh
docker buildx build --platform linux/arm/v7 \
  --build-arg BUILD_FROM=ghcr.io/home-assistant/armv7-base:3.24 \
  --build-arg BUILD_VERSION=2.14.1-ihost.1 \
  --load -t ihost-z2m:2.14.1-ihost.1 zigbee2mqtt
docker image inspect ihost-z2m:2.14.1-ihost.1
```

Emulation is a build/smoke-test aid only. A physical iHost runtime check remains
necessary before treating serial access or the coordinator as verified.
